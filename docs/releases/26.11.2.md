# koinon 26.11.2

koinon 26.11.2 corrects the initial-index checkpoint written by the installation workflow. The installer now records the revision returned by the native repository after persistence, so a newly saved index is not mistaken for a manual configuration change.

An interrupted 26.11.1 installation keeps its original plan, provider settings, protected folders and historical checkpoints. Recovery requires an explicit operator resume of that same plan. A narrowly checked, append-only reconciliation can recognize an untouched queued index whose original checkpoint contains a null revision. Changed configuration, cancelled work and a native index with existing effects remain fenced. The original checkpoint is retained.

Apply this release with the normal migration and role checks, then inspect the installation receipt before choosing resume. Do not delete or reseed its journal. The workflow has no automatic retry for an uncertain outcome. Read [native knowledge provisioning](../operations/installation-knowledge.md) and [first start](../operations/first-start.md) for the operator sequence.

All distributions use CalVer `26.11.2` and the official pyfly `26.10.32` runtime. Use matching packages and checksums from [GitHub Releases](https://github.com/fireflyframework/firefly-koinon/releases). The public API operation set is unchanged by this installer fix.
