# koinon 26.10.1

koinon 26.10.1 uses CalVer `YY.MM.Patch`: `26` is the year, `10` is the month, and `1` is the patch within that month. The backend, native document/structured/storage packages, Python/TypeScript/Java SDKs, Angular library and desktop MCP extension share this version. The runtime uses official pyfly 26.10.24.

## Knowledge and integration workflows

Use Library to organize documents, datasets and reviewed knowledge. Chat combines authorized retrieval and bounded queries with streaming answers, citations and inspectable provenance. Proposed knowledge changes require human review before they are applied. Organization settings control knowledge sources, access, model connections, people and corporate profile synchronization. Personal project memory is opt-in, limited to the owner's chats with matching knowledge scope, and rechecks the complete authorization chain. Each generation records immutable memory dependencies alongside source evidence. Sharing and curating an answer that used remembered context requires a separate explicit decision.

Python, TypeScript and Java SDKs expose the headless API. The Angular library and custom elements support embedded interfaces with host-owned authentication. The desktop extension forwards MCP tools, resources, prompts and supported in-chat review capabilities to your configured koinon server. Organization identity settings customize names, images, colors and bundled Manrope or Inter typography; generated assistant identity follows the authorized organization configuration.

## Install and configure

Obtain versioned distributions and `SHA256SUMS` from [GitHub Releases](https://github.com/fireflyframework/firefly-koinon/releases). Verify each downloaded archive against its checksum before installation. Release downloads are separate from publication to PyPI, npm or Maven Central.

| Component | Requirement and guide |
| --- | --- |
| Backend and workers | Python 3.13, PostgreSQL, configured storage and OIDC; start with [guided setup](../guides/knowledge-setup.md) and [deployment](../operations/production.md). |
| Python SDK | Python 3.12 or later; follow the [Python tutorial](../guides/headless-python.md). |
| TypeScript SDK | Node.js 22 or later, or a compatible host transport; follow the [TypeScript tutorial](../guides/headless-typescript.md). |
| Java SDK | Java 21 or later; coordinates `org.fireflyframework:koinon-sdk:26.10.1`; follow the [Java tutorial](../guides/headless-java.md). |
| Embedded interface | Follow [embedding](../guides/embedding.md) for Angular and custom-element host integration. |
| Desktop MCP extension | A compatible host, Node.js 22 or later, an HTTPS MCP endpoint and a scoped token; follow [desktop installation](../integrations/desktop.md). |

Back up existing data, object stores and encryption keys before upgrading. Use the [migration and recovery guide](../operations/storage-migration.md) to preserve retained installations. Configure and verify your own identity provider, model endpoints, cloud permissions, TLS and backup/restore procedures for the target environment.

## Capability and validation records

Use the capabilities reported by your deployment when selecting operations. Curated-knowledge RLM, general durable bulk intake/query batches and complete retained-domain migration parity have separate implementation and qualification requirements; changing the package version does not enable them. MCP host review support also depends on the host's advertised capabilities.

The [qualification history](../operations/qualification.md) records checks on specific revisions, installed artifacts and environments. Historical results retain their original scope. A local build, a hosted check, a downloaded release package and an operator deployment each require their own recorded result. The [earlier release record](26.10.0-alpha.1.md) remains available for installations using that version.
