# koinon 26.11.9

## Preserve every document read during RLM answers

RLM may inspect metadata from several authorized documents before reading the passages it needs. The evidence record now retains all of those document identities, including documents whose metadata was inspected but whose text was not selected for the answer. Citations still identify the passages actually used.

Each recorded document remains subject to the original token scope, current catalog permissions and workspace checks. Later Audit and answer delivery can therefore enforce revocation for the complete read set. A search no longer fails simply because a metadata-only read falls outside the final citation subset.

## Wait for worker capacity without cancelling active work

Communication and corporate-profile workers defer a claim when the process has no available work capacity. A waiting consumer no longer cancels another consumer that already holds an admitted task. Errors after admission remain visible, and capacity limits are unchanged.

## Update the installation

Use `26.11.9` across runtime packages, SDKs and interface assets, with pyfly `26.10.32`. This patch does not change database migrations or role provisioning. Preserve installation history, original files, source versions and communication outcomes when updating images. Do not rerun first-start jobs or replay uncertain messages as part of the update.

After API and worker readiness, verify a conversation over multiple documents with the configured model, inspect its sources and Audit, and check background processing under the installation's normal capacity limits. See the [installation guide](../operations/installation.md), [knowledge setup](../guides/knowledge-setup.md) and [worker operations](../operations/workers.md).
