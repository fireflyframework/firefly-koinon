# API and SDK reference

Python, Java and TypeScript expose the same canonical headless API. The table records concrete SDK methods; it does not count browser-only authentication or retained domain routes outside this contract.

This canonical contract contains 237 operations. Resource operations require the caller's current membership, permissions and resource scope. Bearer credentials also enforce their saved expiry and bounds. Authorized-application management requires a verified interactive user session; personal tokens and application credentials cannot manage authorizations. [Read about authorized applications](../guides/authorized-applications.md).

[Download the operation manifest](sdk-contract.json) and [complete wire schemas](sdk-schemas.json). The maintained generator checks source mappings and schemas without starting the backend.

Browse [API areas](api/index.md), [wire models](models/index.md) and the [SDK runtime reference](sdk-runtime.md) for parameters, constraints and connection ownership.

TypeScript communications methods use the separately loaded `createCommunicationsApi` factory from `@fireflyframework/koinon-sdk/communications`. Pass the same `KoinonTransport` used to construct `KoinonClient`; the `communications.*` names below refer to the returned API. This keeps email and notification management out of applications that only use knowledge or chat. Python exposes those methods on `KoinonClient`; Java exposes the corresponding typed API groups.

## Request behavior

New conversation export and share reviews save a nullable typed `identity` with product/assistant names, organization branding revision/origin and configuration digest. The review revision binds that identity; later organization changes do not rewrite saved reviews, exports or shared conversations. Historical null means not recorded. JSON exports retain machine roles and separate display names. See the [three-language export and sharing workflows](../guides/exports-sharing.md) for preview, explicit confirmation, authenticated download and recipient reads.

Dataset file append requires a stable Idempotency-Key, accepts one bounded multipart file and returns its canonical file-version and new table identities. Existing snapshots are retained. Native sections commit independently; pending or failed intake blocks dataset query/schema until reconciliation. Exact key/payload replays recheck permissions and return the stored completed receipt without native work. Unknown outcomes are never retried automatically. [Durable file batches](../guides/bulk-intake.md) provide a separate bounded asynchronous lifecycle and explicit receipt reconciliation. PostgreSQL concurrency and configured-provider acceptance remain separate qualification gates.

Use endpoint-declared filters. Totals and page metadata are present only when the server supplies them. Cursor values are opaque. Closing a stream releases the connection; cancel the durable run separately to stop processing.

Content writes require the caller's current revision. Optional avatar conditionals use `If-None-Match`; stream resumption uses `Last-Event-ID`. These are separate from the `If-Match` precondition on content replacement and reingestion.

Known fields have named DTOs and typed values. Opaque business JSON preserves null, booleans, numbers and exact strings recursively. A successful SDK build or contract test does not qualify a configured model provider or a production deployment.
