# Native structured context migration

Upstream: `fireflyframework/flyquery` commit `20b8d704171209dadbc3e21668f5439d2336e9ea`. Python imports remain under `flyquery`; package distribution is `firefly-koinon-structured`.

Changes cover native `pyfly.agentic` imports, application-owned `AgentFactory` binding, and `structured.*` component/factory names. Controller request mappings remain unchanged; the root application projects their compatibility namespace. Prompt-cache behavior is tested with a native context and controlled model.

Schema metadata is `flyquery.models.entities.Base.metadata`, independent of root catalog metadata. Tables retain `flyquery_*` names and require PostgreSQL/pgvector. Retained Alembic migrations use a distinct migration version table when composed.

All 32 session-injecting constructors explicitly qualify `structured.sessions`; the factory borrows the `structured` datasource from the application-owned native `DataSourceRegistry`. `structured.admin_sessions` separately borrows `structured_admin`. Settings refuse unbound storage. Token repositories borrow the same runtime sessionmaker and engine; even the compatibility `from_url` constructor requires a matching registered datasource and cannot create an unmanaged engine. The 159 repository/controller/stage session contexts use native `infrastructure_unit` to join an existing transaction or own a short unit. An actual SQLite/native transaction test first demonstrated the old committed-write leak and now verifies outer rollback.

`WorkspaceService.provision(tenant_id=..., workspace_id=..., name=..., slug=...)` preserves a preallocated canonical UUID through the explicit admin repository, rejects tenant/slug conflicts, and never substitutes a random runtime workspace. Native DI constructs the service with both runtime and admin repositories. Original workspace creation also uses that control-plane repository; content operations retain the runtime repository.

Runtime roles require `NOBYPASSRLS`; the trusted ContextVar GUC hook supplies tenant/workspace per transaction. Ingest events carry their persisted tenant/workspace scope before the worker loads a job; disagreement is refused. Retention and callback workers enumerate only tenant/workspace IDs through the admin repository, then perform every content read/write under a validated workspace context on runtime repositories. Worker actor attribution is server-owned. Legacy queued events lacking scope require reconciliation/republication and fail closed. No worker runtime connection uses the primary catalog datasource or bypass role.

Prompts remain the packaged YAML originals. Thin compatibility views use native `pyfly.agentic.prompts.PromptLoader` and `PromptTemplate`, retaining the original tuple API and legacy field names. A narrowly isolated overlay on the native compiled template environment preserves `StrictUndefined`, block trimming and trailing-newline behavior; the current native public API does not expose those environment options. Native rendering and metadata remain authoritative, with tests for the native object, strict failure, exact whitespace and YAML metadata. Agent construction remains owned by the root `AgentFactory`.

The historical source gate checks 18 normalized baselines, allowing the explicit `structured.AgentTokensController` stereotype substitution. Three service-specific agent/cache/GUC-documentation variant hashes record native migration; original hashes remain in the manifest/pins. The GUC implementation is unchanged; its documentation now describes scoped workers rather than a bypass assumption. This does not establish current source equality with standalone flycanon. All 108 upstream test/resource files are frozen under `provenance/upstream-tests` with SHA256 provenance. Active SQL assertion doubles adapt to the native unit seam in tests only; production has no fake-factory fallback.

The local unit gate passes **556 tests**, including 533 retained cases and native Data, prompt, provider and SQL-name boundary cases. Ruff passes. Pyright reports zero errors and 11 warnings in retained query/semantic code. The independently operated owned PostgreSQL gate additionally verified canonical workspace provisioning, tenant conflict, actual DatasetService missing/foreign RLS denial and a shared native transaction rollback; its separate evidence is `work/control/native-domain-data-acceptance.json` in the parent workspace.

Both qualified session beans return `StructuredSessionBinding`, preventing native primary-datasource auto-configuration from mistaking an admin sessionmaker for the application's primary sessionmaker. A real composed-context regression established this boundary. `TenantGucCustomizer` implements the native after-begin SPI for the runtime datasource; the SPI also disables the native AUTOCOMMIT readonly fast path so `SET LOCAL` survives through the actual read transaction. Primary and admin datasources do not inherit runtime tenant state.

Redis-backed infrastructure and provider failures fail actionably by default. In-memory adapters and lexical/provider fallback require explicit isolated-development flags. Existing local models use the native provider's JSON-schema output transport through the application-owned agent factory. SQL binding strips only exact authorized qualified table aliases advertised by the schema inventory; unknown schemas and multiple statements remain unchanged for the original scope/firewall rejection.

Actual local qualification additionally completed CSV ingestion, a two-column schema, direct SQL and model-generated SQL returning a real sum of 12 against persisted Parquet. Existing local models only were used, with no downloads or cloud calls. Evidence is `work/control/knowledge-local-acceptance.json`; its individual checks remain authoritative if another optional document-model check fails. HTTP qualification independently exercised retained dataset/table/snapshot/query-result controllers through real Keycloak authorization-code/PKCE tokens.

Original gaps remain explicit: cloud snapshot staging, result PII enforcement, complete automatic usage/billing, frontend rendering and MCP are not established by the preserved suite. Worker restart/retry and all compatibility write operations remain separate qualification gates.
